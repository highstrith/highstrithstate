## 播放规则

最新要求覆盖上一轮默认点击才加载的方案：首屏只加载当前可见Hero的轻量预览；向下浏览时，只有视口内的一部作品预览获得src，其他卡片保留封面。优先可见的鼠标／键盘目标，其余按距视口中心排序；视频画面至少显露四分之一（大画面上限120px）才候选。滚动离开、筛选、弹窗、后台和减少动态时释放旧源，任意时刻最多一部自动预览。

暂停按钮停止全部预览，并跨语言、选片和滚动保持；访客可直接点作品播放原完整web／mobile版本。节省流量模式与减少动态均不自动请求预览，手动完整播放仍可用。窗口缩小时也检查当前画面是否已经离屏。

## 发布结构

- 源HTML、JS和目录仍使用相对路径，便于本机预览和继续管理作品。
- `scripts/prepare-media-cdn.mjs`以实际公开打包目录为白名单，收集`assets/`与`reel/img/`的图片／视频，排除原片目录、母版、隐藏文件和软链接。输出媒体保留原对象路径。
- 发布时读取公开配置`MEDIA_CDN_BASE_URL`，重写已打包文件对应的静态图片／srcset／延后图片、大图链接、视频及动态JS／JSON媒体引用；脚本、CSS、PDF和页面导航留在Pages。CSS文件留在Pages，其引用图片可改到CDN。不引入浏览器OSS SDK或密钥。
- 发布HTML注入明确的CDN前缀。播放器只接受相对assets路径或该前缀下的assets URL，不能由作品目录指定其他外部媒体站。Hero在设src前使用anonymous跨域模式，配合CORS保持抓帧切换。
- 只接受HTTPS生产前缀；本机测试允许loopback HTTP；拒绝URL内账号密码、查询和片段。输出目录不能与站点相互包含，包括经软链接映射的路径。
- Pages工作流保持main-only及原白名单；固定Node22，复制产物后运行可选CDN转换。仓库变量`MEDIA_CDN_BASE_URL`为空时原样保留同源引用，不发布假域名。

## 后续替换或新增媒体的流程

当前工作流只做地址转换，不会自动上传，凭据也不入仓库：

1. 本地新增或替换素材后，先跑一次 `node scripts/prepare-media-cdn.mjs --site public --media-dir <临时目录>` 生成与公开文件一一对应的上传目录（或用 CI 相同白名单手工打包）。
2. 临时创建有写权限的 RAM AccessKey（用完即禁用），`ossutil cp -r <上传目录>/ oss://highstrith-assets/ --update` 覆盖同名对象。
3. 素材不是哈希命名，覆盖后注意缓存：对象统一 `Cache-Control: public,max-age=600`，访客最多 10 分钟后看到新版本；急用可临时改文件名（HTML 里随之引用）。
4. 再推 main 重新部署页面。

## 外部状态与限制

Bucket `highstrith-assets` 已创建并公共读，对象已上传，媒体已切换上线。用户没有独立域名，大陆CDN需要已备案的加速域名（HTML继续托管GitHub Pages不免除此要求，见[阿里云CDN接入说明](https://www.alibabacloud.com/help/en/cdn/add-a-domain-name)），因此本轮**未开通CDN加速**，直接使用OSS默认域名。上传用的一次性RAM子账号AccessKey已在完成后禁用，本机凭据配置已删除。

已知限制：公共读＋默认域名本身没有防盗链，本次已开启 Referer 白名单（见下）；桶内另有36个0字节目录对象，无害但当前策略无删除权限清不掉。

已做的两项加固（2026-11-01）：

- **缓存头**：286个对象（含36个目录对象共322个）统一为 `Cache-Control: public,max-age=600`，与 Pages HTML 的 10 分钟缓存对齐。用 `ossutil set-meta ... --update -r` 完成；`--update` 只改指定头，`Content-Type`、大小、ETag 均未变（逐对象复验 286 项全对）。注意 `set-meta` 内部走 CopyObject，需要 `oss:GetObjectAcl`／`oss:PutObjectAcl`，否则报「You do not have read acl permission on this object」。
- **Referer 防盗链**：白名单 `https://highstrith.github.io/` 与 `https://highstrith.github.io/*`，允许空 Referer。实测：本站页面引用 200、根路径 200、无 Referer 200、外站 403、构造域名 `highstrith.github.io.evil.com` 403；线上五个页面零 4xx。**OSS 的 Referer 匹配是前缀匹配**，所以白名单条目必须带斜杠——若只写裸域名 `https://highstrith.github.io`，`https://highstrith.github.io.evil.com/` 会被放行。代价是 Referer 恰为裸域名（无路径）时返回 403，浏览器不会产生这种值。以后换域名或加自定义域名必须同步加白名单，否则全站媒体 403。


GitHub Pages仍承载首次HTML和代码，图片／视频迁到OSS不能解决GitHub入口本身完全不可达的情形。本机实测下载39.5MB/s，未在他人网络环境测速，不能据此宣称所有地区国内速度已提高。

此前Netlify试验曾在Free账户建立独立副本`iridescent-panda-be0b5b`，未覆盖原GitHub站或旧`highstrith`项目；直连媒体仍慢，用户随后改选本方案，因此不把该试验副本作为正式入口。
