## 播放规则

最新要求覆盖上一轮默认点击才加载的方案：首屏只加载当前可见Hero的轻量预览；向下浏览时，只有视口内的一部作品预览获得src，其他卡片保留封面。优先可见的鼠标／键盘目标，其余按距视口中心排序；视频画面至少显露四分之一（大画面上限120px）才候选。滚动离开、筛选、弹窗、后台和减少动态时释放旧源，任意时刻最多一部自动预览。

暂停按钮停止全部预览，并跨语言、选片和滚动保持；访客可直接点作品播放原完整web／mobile版本。节省流量模式与减少动态均不自动请求预览，手动完整播放仍可用。窗口缩小时也检查当前画面是否已经离屏。

## 发布结构

- 源HTML、JS和目录仍使用相对路径，便于本机预览和继续管理作品。
- `scripts/prepare-media-cdn.mjs`以实际公开打包目录为白名单，收集`assets/`与`reel/img/`的图片／视频，排除原片目录、母版、隐藏文件和软链接。输出媒体保留原对象路径。
- 发布时读取公开配置`MEDIA_CDN_BASE_URL`，重写已打包文件对应的静态图片／srcset／延后图片、大图链接、视频及动态JS／JSON媒体引用；脚本、CSS、PDF和页面导航留在Pages。CSS文件留在Pages，其引用图片可改到CDN。不引入浏览器OSS SDK或密钥。
- 发布HTML注入明确的CDN前缀。播放器只接受相对assets路径或该前缀下的assets URL，不能由作品目录指定其他外部媒体站。Hero在设src前使用anonymous跨域模式，配合CORS保持抓帧切换。
- 只接受HTTPS生产前缀；本机测试允许loopback HTTP；拒绝URL内账号密码、查询和片段。输出目录不能与站点相互包含，包括经软链接映射的路径。
- Pages工作流保持main-only及原白名单；固定Node22，复制产物后运行可选CDN转换。仓库变量`MEDIA_CDN_BASE_URL`为空时原样保留同源引用，不发布假域名。

## 上传准备与接入顺序

本轮已生成286个图片／视频对象，合计313,816,273 B：

- 上传目录：`/Users/linjunjie/.codex/visualizations/2026/11/01/01a195ab-eaf4-7102-8c04-d8fd996e1f34/oss-media-upload/`
- 字节数／SHA-256清单：同目录旁`oss-media-manifest.json`。

复用官方开源[aliyun/ossutil](https://github.com/aliyun/ossutil)和[阿里云OSS＋CDN指南](https://www.alibabacloud.com/help/en/oss/user-guide/cdn-acceleration)，没有复制第三方上传代码。示例命令使用实际环境变量，不在仓库或网页保存凭据：

```sh
# 按官方文档在本机配置受限RAM／STS上传身份。
# MEDIA_DIR为上述上传目录；OSS_DESTINATION为实际bucket及可选前缀；OSS_REGION为该bucket实际地域。
ossutil sync "$MEDIA_DIR/" "$OSS_DESTINATION" --update --region "$OSS_REGION"
```

不使用`--delete`，以保留旧哈希对象供缓存和回滚使用。若OSS目标前缀是`highstrithstate/`，CDN base也必须包含对应前缀；不得把assets层级扁平化。

1. 在用户确认费用与域名安排后准备实际Bucket和CDN域名，配置HTTPS。可以使用私有源站＋CDN回源鉴权；不要把临时签名URL写进公开目录。
2. 上传本轮目录中的文件，保持对象层级；设置或核对WebP的`image/webp`和MP4的`video/mp4`。
3. 在OSS／CDN配置GET、HEAD跨域读取，来源为`https://highstrith.github.io`；允许Range，并暴露Content-Length、Content-Range、Accept-Ranges、ETag。CDN需配置或透传对应CORS响应头。
4. 开启Range回源，验证`Range: bytes=0-65535`返回206、正确Content-Range及字节。哈希资源可长缓存；非哈希文件使用短缓存，覆盖后按需刷新。
5. 核对主封面、精选预览、桌面／手机完整播放、大图、片单、无脚本入口和字节清单，再设置仓库变量`MEDIA_CDN_BASE_URL`并从已验证版本发布main。

启用之后，后续新增或替换媒体也必须先同步OSS再发布Pages；当前工作流负责地址转换，不会自动使用云端凭据上传。
