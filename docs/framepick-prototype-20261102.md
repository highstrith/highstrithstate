# 帧选交互原型：演示状态与未接入服务标注（2026-11-02）

本轮把「帧选 Framepick」交付为**可交互前端原型**：找片—判断—观看入口是真实可用的页面功能；账号、支付、授权放映、创作者投稿与收益结算均未接入，界面上所有依赖这些服务的状态都带「演示」标记，不宣称已实现真实账号、支付或分账。

## 本轮范围与结论

### 1. 已有能力（保留并复用，不重建）

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| 片库发现（搜索、组合筛选、排序、收藏、详情弹窗、深链接） | 页面真实功能 | 数据来自片库记录（`server/framepick-library.cjs` + 生成器），收藏只存本浏览器 |
| 三个榜单 | 每日更新真实；热门／口碑依赖本地服务 | 热门榜是近 10 天「前往原作」去重跳转计数（明确不是播放量）；口碑榜用站内访客评分，未达门槛不展示 |
| 访客评价与评分 | 本地可用，正式站点未部署 | 签名 Cookie 识别访客，可更新／撤回 |
| 账号（邮箱＋密码） | 本地可用（演示） | `server/framepick-accounts.cjs`：scrypt 哈希 + HMAC 会话；访客评价不并入账号 |

### 2. 本轮改善（新增）

- **原型提示条**（页面顶部，可收起）：一句话说明「账号、支付与分账均未接入；带『演示』标记的内容只保存在此浏览器」，入口按钮打开**服务状态弹窗**。
- **服务状态弹窗**（`#statusDialog`）：10 项服务逐条列出「已实现 / 本地演示 · 正式未部署 / 未接入」，每条写明当前行为与**正式接入所需接口和条件**（商户号与回调、签名 URL 与授权期校验、审核后台与结算规则等）。
- **演示购票流程**（`#purchaseDialog` + `reel/framepick-demo.js`）：完整走一遍真实结账必须处理的状态机——未登录 → 未购买（展示拟定 3/5 元与「授权期内反复观看，不是永久拥有，也不是 48 小时租赁」）→ 支付中 → 服务端确认中 → 已购有效（授权期）→ 支付失败 → 已取消 → 退款中 → 已退款 → 授权到期 → 影片下架。全程不发送任何请求、不收费；另提供「演示：支付失败」「演示：影片下架」两个评审入口。
- **我的影院**（`#cinema`，观影计划之后的新区块）：列出本浏览器的演示订单（状态标签、拟定价格、授权期），每条明确「不产生真实付款或放映权益」；「尝试播放」如实提示授权放映未接入；可一键清除演示订单。
- **演示标记体系**：`.state-chip` 三态样式（绿=已实现、金=本地演示、红=未接入）；账号／创作者／观影计划弹窗都带对应标记；创作者入口在创作者模块缺失时自动降级为「未接入」说明，不出现无响应的按钮。

### 3. 依赖后端／授权／支付服务的部分（均未接入）

支付（微信支付／支付宝商户号、下单与异步回调、幂等与对账）、授权放映（媒资加密或签名 URL、授权期校验）、创作者结算（审核后台、合同与分成规则、退款扣减）、搜片 AI 调度。演示数据与生产数据完全隔离：演示订单只存 `localStorage['framepick:demo:orders:v1']`，不上传、不进入片库、不产生真实订单。
