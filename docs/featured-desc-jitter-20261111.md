# 首页精选「板块抽搐」修复（2026-11-11）

## 现象

作品站首页那组精选（5 条，`01 / 05`）来回切换时，整块底板会上下抽动。新加入的《未知之诺》最明显。

## 根因

不是动画问题，是**描述行数不一致导致的内容高度变化**。

精选的右侧信息栏结构是「分类 → 标题 → 描述 → 五条缩略图 → 预览提示」，描述 `#featureDescription` 的高度由字数决定：

| 作品 | 描述字数 | 1680px 处行数 |
| --- | --- | --- |
| 未知之诺 | 69 字 | 4 行（84px） |
| 重置日 | 23 字 | 2 行（42px） |
| Prove It | 8 字 | 1 行（21px） |
| AI患者 | 7 字 | 1 行（21px） |
| 街头篮球 | 20 字 | 1 行（21px） |

切换时描述从 4 行变 1 行，`.feature-info` 高度从 153px 掉到 90px，**相差 63px**。

两个断点表现不同：

- **≥ 801px（右侧栏布局）**：`.feature-bottom` 是绝对/定高的一栏，容器高度不变，但 `align-items: end` 让信息块贴底 → 高度一变，**标题和分类就上下跳 63px**。
- **≤ 800px（底板回到常规流）**：容器高度由内容决定，`heroFeature` 实测跳动 **720px 处 21px、480px 处 19px、390px 处 38px**，整块连同下面的内容一起顶上去。

## 修法

给描述固定预留 4 行，五条的 info 块等高，位置不再变化：

```css
#featureDescription { min-height: 7em; min-height: 4lh; }
```

- `line-height: 1.75` → 4 行 = `7em`（`em` 跟随自身 `font-size`，各断点自动换算）。
- `4lh` 是同一件事的更直观写法（Chrome 109+ / Safari 16.4+），旧浏览器回落到 `7em`。
- 缩略图列表本来就靠 `margin-top: auto` 贴底，多出来的空白会被它吸收，不会把列表顶下去。

## 验收

改前 / 改后，五条逐个切换、记录 `heroFeature` 高度：

| 宽度 | 改前波动 | 改后波动 |
| --- | --- | --- |
| 1680 / 1440 / 1180 / 900 | 0（但标题跳 63px） | 0 |
| 720 | 21px | 0 |
| 480 | 19px | 0 |
| 390 | 38px | 0 |

`./scripts/run-portfolio-tests.sh`：32/32 通过，静态快照一致。

## 以后加片要注意

描述**控制在 4 行内**（1680px 桌面约 70 字，390px 手机约 4 行更宽松）。超过 4 行会重新撑高，抽搐就会回来。

如果哪天确实需要更长文案，正确做法是再加预留行数（把 `4lh` 改成 `5lh`、`7em` 改成 `8.75em`），而不是删掉这行 `min-height`。
