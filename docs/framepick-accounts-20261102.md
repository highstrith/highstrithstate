# 帧选账号与登录（2026-11-02）

- 状态：**已实现基础能力**。登录方式的选择是本轮实现决定，不是 PRD 中已确认的用户决策；PRD 第 15 项「登录与恢复」仍留有未定规则。
- 依据：`docs/framepick-prd-20261102.md` 第 7.2 节、第 12 节与第 15 节待决策清单。

## 1. 为什么选邮箱 + 密码

PRD 只要求「账号需要能跨设备恢复订单和观影权益」，并明确**不默认指定短信服务或微信接入**。本轮选择邮箱 + 密码，理由是：

- 不依赖第三方平台、短信服务商或 OAuth 应用审核，个人站点即可承载。
- 邮箱天然是跨设备的稳定标识，能满足「换设备找回订单」的目标。
- 一旦将来接第三方登录，邮箱仍可作为账号合并的主键。

这不是最终结论。若后续要接微信／手机号，应作为**附加登录方式**接入同一账号，而不是另起一套账号。

## 2. 实现了什么

| 项 | 做法 |
| --- | --- |
| 存储 | `~/.framepick/accounts/`（站点根目录之外，不进 Git、不进发布产物），`FRAMEPICK_ACCOUNTS_DATA_DIR` 可临时改指 |
| 密码 | scrypt（N=16384, r=8, p=1）随机盐哈希，库中永不出现明文；校验用 `timingSafeEqual` |
| 会话 | 随机 32 位十六进制 ID + HMAC-SHA256 签名，`HttpOnly`、`SameSite=Lax`、`Path=/api/framepick`、30 天，HTTPS 下自动加 `Secure` |
| 接口 | `GET /api/framepick/accounts/session`、`POST …/register`、`POST …/login`、`POST …/logout` |
| 防护 | 来源校验（跨站写拒绝）、登录失败限流（同 IP + 邮箱 10 分钟 8 次）、注册限流（同 IP 1 小时 5 次）、未知邮箱与密码错误返回同一提示（避免账号枚举）、登出即失效服务端会话 |
| 前端 | 页头「登录 / 注册」入口与账号弹窗；登录后显示昵称，**不跳转不刷新**，打开的详情与筛选条件保持不变 |

账号失败时原作跳转、浏览与访客评价照常可用。

## 4. 与访客评价的关系

- 登录**不会**合并此浏览器已有的访客评价，也不能凭昵称认领旧评价（PRD 7.2：身份合并规则待定，不能让同一份评价被重复纳入均分）。
- 账号下的评分规则（同一作品一份有效评分）在评价服务接入账号时再实现。
- 页面已把这条边界写在账号弹窗里，不静默合并。

## 5. 安全边界

- 这是**本地共享服务**，正式 GitHub Pages 不运行它；线上目前是「账号服务尚未部署」的如实状态，不是故障。
- 会话 cookie 只在 `/api/framepick` 路径下发，与评价服务同一路径策略；跨站提交默认拒绝。
- 账号数据文件权限 700／600；数据损坏时**拒绝启动**，不会用空库覆盖已有账号。
- 不含支付、订单与观影权益——这些属于阶段 C，账号只是前置。
