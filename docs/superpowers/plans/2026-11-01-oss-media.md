# OSS media delivery implementation plan

> Execute inline in the existing linked worktree, following the user's explicit implementation direction. Keep completed changes reviewable and test each behavior before implementing it.

**Goal:** Keep HTML on GitHub Pages, compress cover media and serve images/video through a configurable OSS CDN, with video previews confined to the viewport.

**Architecture:** Preserve relative media paths in source. A publishing transform copies only public image/video objects to an upload directory and rewrites the published HTML/JS/JSON/CSS references to an explicitly configured HTTPS CDN prefix. The existing single-preview scheduler selects a visible card or the visible Hero and releases the previous source; no new player or framework.

**Tech Stack:** Native JavaScript, Node, FFmpeg, Python Playwright, official Alibaba Cloud ossutil.

**Spec:** User's 2026-11-01 instruction in this chat; reflected in 产品需求.md after verification.

## Constraints

- hero-fireflies.mp4 < 3,000,000 bytes; preserve complete duration and source aspect ratio. Other current Hero previews < 3,000,000 bytes.
- Cover images are WebP and < 200,000 bytes. Keep full-resolution lightbox images and original artwork.
- At most one automatic preview; no offscreen video sources; background/dialog/reduced-motion handling remains. Keep manual full playback.
- Media CDN configuration must not relocate HTML, scripts, styles, app navigation or the PDF. Never accept arbitrary external media origins through catalogue data.
- No invented bucket/domain or embedded credentials. External upload and activation require the user's real account/configuration; no purchase or plan upgrade.
- Stop Netlify evaluation. Its existing experimental copy may remain, but it is not the chosen delivery path and existing sites must not be overwritten.
