# 两处标题的弹性文字

2026-10-30，用户明确选择“像Hello_world那样，文字随鼠标逐字拉伸、波动、回弹”，指定首屏“想象，在此成片”和下方“导演工作台”。

开工前检索评估了[Adasha/proximity-effect](https://github.com/Adasha/proximity-effect)及[kinetic-typography](https://github.com/Ashborn-047/kinetic-typography)。本站已有导演标题的局部实现，复用它比引入额外动效库更适合；没有复制外部代码或资源。

执行方案：把`director-word.css/js`的目标从一处扩大到两处，各自保存影响值／rAF和独立滤镜；首页只改资源版本及旧拆行标记；新增首屏行为验证，再检查导演标题、语言及小屏。主要风险是滤镜重名、同一页面多个实例共享状态，以及翻译／拆行脚本反复覆盖字形；用标题ID前缀、各自闭包和移除首屏`data-lines`处理。

- 首屏外层`.hero-title-wrap`继续入场，字形内部承担悬停反馈。原字号、正常占位、文案和链接不变。
- 鼠标附近字形纵向最多拉伸18%，轻微倾斜和橘色反馈；移动时最多2.2px位移波动，移开归位。
- 不给两个标题加背景反色；联系区反色保持独立。触屏及减少动态静态展示；滚动、失焦和后台清理，收敛后停止调度。
- 标题各自提供完整可访问名称，英文按词换行，语言切换后重建内部字符及滤镜。

验证：`python3 tests/director-word-smoke.py -v` 4项通过；首屏未接入时新增用例失败，接入后通过。覆盖真实鼠标近字拉伸／恢复、导演标题保持独立、12个初始滤镜ID唯一、中英切换、触屏／reduce／脚本失败和项目跳转。既有5档中英文布局1项、Pages打包1项、JS语法和Git空白检查通过。首屏正常状态截图见`elastic-titles-20261030/hero.png`。验证环境为本机Chrome，未取得真实手机及Safari结果。仅本地提交，未发布。
