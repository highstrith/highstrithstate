## 可迁移的共同优点

以下是对上述项目的综合判断，用于指导本轮设计，并非对星数与网站效果之间因果关系的断言。

1. **内容有主次。** 个人定位说明创作领域，精选作品建立第一印象，完整目录满足继续探索。对影视作品集而言，画面应该比履历和装饰更早出现。
2. **识别度来自专业表达。** Bruno 的交互直接表现创意开发能力；本网站适合以现有影像素材、节奏与构图表达创作者身份。
3. **反馈解释操作。** 筛选、播放、关闭等状态有明确反馈，过渡服务理解。装饰动画不能妨碍操作，也不能让减少动态效果的访客失去内容。
4. **媒体体验包含工程细节。** 画框预留尺寸、海报先行、媒体按需加载、关闭后释放播放资源，比单纯增加视觉效果更能改善观看体验。
5. **成熟交互尊重平台能力。** 语义按钮、原生控件、键盘操作、焦点返回和渐进增强，应与视觉质量一起验收。

## 本轮应用方向

将网站整体调整为“当代影像工作室”式的个人作品集：以亮色中性纸白 `#f4f4f0` 为页面底色、墨黑 `#171918` 为主要文字与边界、橘色 `#e46740` 为少量行动和身份点缀。通过排版层级、留白、细线和真实作品画面建立秩序，保持中英文信息一致。

- **精选首屏：** 使用现有真实作品建立第一屏，明确创作者身份和观看入口；不虚构客户、荣誉、服务成果或新增宣传素材。
- **全部作品：** 保留完整作品展示能力，并提供可筛选的作品目录。精选与全部作品共用稳定作品 ID 和同一份目录数据。
- **按需媒体：** 封面优先，用户进入观看流程后再加载相应完整视频；关闭、切换和页面隐藏时清理或暂停相关播放。保留加载、失败重试、移动端选源及减少动态效果的合理行为。
- **原生交互：** 保留原生纵向滚动，使用原生 `<dialog>` 承载独立观看与必要弹层，保留键盘关闭、背景隔离和焦点返回。媒体控件继续基于原生 `<video>`。
- **功能边界：** 保留本地上传与作品管理页的新增、编辑、删除和媒体管理能力。`serve.js` 只为本机提供管理 API；GitHub Pages 继续发布静态展示文件，公开站不能把本地管理能力描述为线上上传能力。
- **实现约束：** 本轮从结构和交互原则借鉴，自主编写实现，不复制第三方项目代码，不新增前端依赖。此研究文档不构成引入上述库或发布网站的决定。

本文件记录研究依据与应用方向。最终实现、验证结果及交付状态由项目固定文档和实际验收记录说明。
