# 首页精选预览固定画框

用户反馈《重置日》与其余四部来回切换时有大小改变的错顿，明确要求给所有视频比例固定一个预览区域。

## 根因与方案

真实Chrome正常动效复现：1100px下《重置日》画框776×461.890625，其余四部776×440.890625；820px下宽496px、高度同样变化21px。英文说明多两行时可变化42px。画框、整个hero及右侧栏同高；描述由一行变两行正好多21px。原因是中等屏幕取消了画框比例，仅保留440px最小高度，Grid行又按右侧说明的固有高度伸展。

五部海报与视频层原本均contain同框；真实视频既有横幅854×480／960×540，也有540×960竖幅。此问题由布局决定，并非《重置日》源文件被改动。

开工前评估 [Bootstrap Ratio helpers](https://getbootstrap.com/docs/5.3/helpers/ratio/) 的固定父框包裹媒体方式，并查阅MDN aspect-ratio／object-fit。保留本站侧栏排版和原生CSS，不复制模板、不引入包。

步骤：逐rAF真实切五片再回首部，建立失败回归 → 固定父区域及Grid行，解除说明固有高度影响 → 检查正常播放、溶解、延迟、失败及横竖原比例 → 桌面／平板／手机双语与既有媒体调度验证 → 同步文档、本地提交。

- 桌面／平板height=clamp(480px,42vw,640px)，同一视口下所有作品始终同高；Grid行minmax(0,1fr)，画框100%宽高、min-height:0。右侧栏min-height:0、必要时内部滚动，文字不能撑大画框。
- 800px及以下保留原有上下排版和16:9画框；高度由画框宽度决定，与影片原比例无关。
- 海报、视频和冻结过渡层共用画框，保持contain等比适配，不拉伸原片。五部预览选择、实际播放轮播和完整播放器保持。

## 验证

- 新增`tests/hero-frame-smoke.py`，先运行旧实现取得21／42px变化失败，再验证修复后通过：2项／12参数场景、66.907s、exit 0。先等待原首页入场结束，再逐rAF记录切片阶段，避免把正常首次入场缩放误判为切片跳动。
- 真实五部顺切并回首部，包含原生540×960竖片；正常元数据、500ms淡化、视频请求延迟及失败均覆盖。四宽中英的画框分别恒定为1034×604.797（1440px）、776×480（1100px）、496×480（820px）、350×196.875（390px）；桌面整体和右栏尺寸也不变，海报与视频层始终同框、fit一致。
- 既有Hero7项、五部完整播放选择与手机控件布局2项、手动暂停保留1项通过；实际Pages打包1项和Git空白检查通过。
- 12组回归PNG／逐帧JSON及独立审查截图保存在同名目录，1100中文、820英文和390手机截图已人工查看。来源媒体和生产JS无改动。
- 独立复核确认820／1100英文五个选择按钮与暂停控件均可通过Tab到达；320手机画框280×157.5，文字放大200%后Hero说明自然增高，控件无遮挡。极端字号诊断下现有页头存在文字重叠及整页宽345px的边界，Hero本身仍280px、无内部横向溢出；此页头问题不由本次改动引入，本轮未扩大修改范围。
