# 媒体优化使用说明

在本地工作区操作；线上 GitHub Pages 不执行转码。原视频保持不变。

首次准备固定工具（独立缓存，不安装到网站）：

```sh
npm install --prefix "$HOME/.cache/portfolio-media-tools" --no-audit --no-fund --save-exact ffmpeg-static@5.3.0
```

之后在项目目录运行一个命令：

```sh
node scripts/optimize-media.mjs
```

生成 20 秒无声预览（原片不足 20 秒时为全片）、720p 以内的完整手机版、必要的桌面 MP4 索引重排版本，更新 works.json、页面内完整快照和无 JS 作品链接。视频解码验证通过后才采用输出；单个作品失败时保留旧引用，继续其他作品，并以非零状态报告失败。已有摘要文件会复用，源文件、工具或编码脚本变化会生成新 URL。

工具也可通过 `FFMPEG_PATH=/absolute/path/to/ffmpeg node scripts/optimize-media.mjs` 指定。当前固定 arm64 工具实际返回 FFmpeg 6.0；确切工具哈希、源文件哈希与资源指标保存在 `assets/optimized/media-report.json`。

只编辑作品名称或说明后，同步静态回退即可：

```sh
node scripts/sync-work-catalogue.mjs
```

管理页替换原视频会清空旧预览、手机版和桌面衍生引用；重新运行生成命令后公开页使用新资源。没有预览文件的作品在公开列表显示封面，仍可点击播放原片。工具不会自动清理历史生成文件，确认不再被目录引用后再清理。

验证命令（浏览器测试需先运行 `node serve.js`）：

```sh
node tests/media-integration.mjs
node tests/media-optimizer-integration.mjs
node tests/optimized-media-integration.mjs
node --test tests/works-api-integration.mjs
python3 tests/playback-optimization-smoke.py
python3 tests/static-site-smoke.py
python3 tests/site-redesign-smoke.py
python3 tests/media-smoke.py
python3 tests/mobile-player-smoke.py
```

本轮只生成、验证并提交本地文件，没有推送或部署。
