# V2 手机加载优化

2026-10-08，针对手机首页加载慢的反馈，保留白色 V2 的设计、所有作品及本地上传管理功能，只调整图片加载。

## 诊断与效果

使用同一 Ego 浏览器任务、390×844 / DPR 2 / 触屏、禁用缓存，模拟 1.5 Mbps 下行、150ms 延迟。每次导航前重新应用网络限制，首次首页不滚动、不点击。以下是本地 HTTP 的单次对照，不能代替真实手机或线上网络的速度保证。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 首页初始图片响应体合计 | 5,191,903 B | 166,630 B |
| 主封面响应完成（从导航起） | 28.368 秒 | 0.707 秒 |
| 全部初始图片响应完成 | 28.368 秒 | 1.509 秒 |
| 初始 MP4 请求 | 0 | 0 |

初始图片减少 96.79%。这些时间是资源响应完成时间，不是 LCP 或整页交互完成时间。优化前两张 PNG 占 4,248,987 B；隐藏二维码还提前下载 187,476 B。手机现在选用 960px WebP 主封面，原 2,170,977 B 的《重置日》封面对应版本为 39,600 B；《趴着办公早该知道》为 73,100 B，原图仍完整保留。

实际截图：[手机首页](studio-redesign/mobile-loading-after.png)。原始测量：[对照报告](studio-redesign/mobile-loading-report.json)。尺寸、源/输出哈希及字节见 [图片构建报告](../assets/optimized-images/image-report.json)。

## 实现与维护

- 16 张源图生成 50 个 WebP 尺寸版本（160/480/960/1600px，按原宽封顶），质量 80，保留完整比例，不裁切或放大。
- 原路径作为清单键，输出路径包含原图和编码配置的哈希；原图或配置变化后得到新 URL。清单内嵌到 HTML，静态主封面在 JavaScript 执行前就能正确选图。
- Hero、肖像、卡片、无脚本目录使用 srcset/sizes；精选按钮仅加载 160px 小图；卡片图片全部 lazy；播放器使用轻量封面。二维码交互时才设 src。
- works.json、原素材、V1/V2 历史标签不改。未知的新图片仍回退原始路径；管理 API 和上传/替换/删除字段合约不扩展。

新增或替换封面后，发布前在项目目录运行：

```sh
node scripts/optimize-images.mjs
node scripts/sync-work-catalogue.mjs
```

生成器使用既有 `~/.cache/portfolio-media-tools/node_modules/ffmpeg-static/ffmpeg`；其他机器可通过 `FFMPEG_PATH` 指定本地 FFmpeg。它只生成图片资源及清单/报告，不自动同步页面，不安装前端依赖，不重写源图或作品数据。

## 验证

- 新增真实 HTTP 手机冷启动预算测试先 RED（5,193,740 B，捕获两张原始大 PNG），修复后 GREEN（168,460 B，含 HTTP 头）；图片预算 400 KiB，主封面物理宽 960px，所有图片响应 200、初始零 MP4。
- 18 项完整浏览器回归通过（46.184 秒）：手机/桌面播放、精选切换、未来新增首位、搜索/筛选、中英、二维码、无脚本/file/子路径、播放器恢复，以及临时目录实际上传、编辑、删除。
- API、目录同步、图片生成和实际 Pages 打包共 20 项 Node 回归通过。图片回归覆盖原图不变、比例/尺寸、不放大、缓存与重新生成一致、更换原图后新 URL、重复同步和缺失清单回退。
- 媒体引用、脚本语法、Git 空白检查通过；16 个源图和 50 个输出哈希与报告逐一匹配。此次没有改动视频编码，因此不重复完整视频解码测试。

浏览器为 Chromium 触屏模拟；未进行安卓/iOS 实机测试。
