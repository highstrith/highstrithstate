### 2026-11-04 阶段范围更新（优先于下方早期规划）

## 2. 产品定位与目标

### 2.1 产品定位

帧选帮助普通观众发现值得观看的 AI 影像，并计划通过授权放映，让观众以较低的单片价格获得完整故事体验，让创作者从有效交易中获得收入。

“代替电影院”是用户提出的长期愿景，落到产品上是：质量优先、完整观影、清晰选片、低门槛单片消费。它不等于承诺现有片源已经具备院线发行资质、均为院线电影或可以直接收费播放。

### 2.2 产品目标

1. 让观众通过分类、题材、榜单和评分快速找到想看的作品。
2. 持续发现优质新作品，既覆盖爆款，也能发现粉丝很少但质量过硬的创作者。
3. 保留免费原作发现与外链观看，逐步补齐授权正片的站内购买和观看。
4. 建立投稿、审核、授权、上架、订单收益及结算的创作者发行闭环。
5. 让免费外链、站内授权电影、原平台数据和本站数据清楚区分。

### 2.3 目标用户

| 用户 | 主要需求 |
| --- | --- |
| 普通观看者 | 少花时间挑片，判断质量，观看免费片源，按片购买喜欢的完整电影 |
| AI 电影创作者 | 获得展示和发行机会，提交作品，了解审核进展，查看真实订单收益 |
| 平台运营者 | 稳定扩充片库，核实来源与授权，审片、编排榜单、处理评价和订单问题 |

创作者粉丝、AI 行业学习者与普通观众可以同时存在，但在经营分析中应分开，不能把同行浏览或朋友支持当成普通观众的持续购买需求。

**免费发现流程：** 访客进入 → 查看榜单或筛选 → 打开详情 → 前往原平台观看 → 返回收藏或评价。

**付费观影流程（目标）：** 选片 → 查看真实价格及授权期限 → 登录／注册 → 确认订单 → 支付 → 服务端确认 → 进入我的影院 → 授权期内反复观看。

**创作者流程（目标）：** 注册 → 申请创作者身份 → 提交成片和权利材料 → 平台审片与核验 → 确认发行条件 → 上架 → 有效订单产生待结算收益 → 处理退款与结算。

**片库更新流程（目标）：** 搜片 AI／人工推荐／创作者投稿 → 候选池 → 信息核实与去重 → 看片和质量评估 → 内容及授权审核 → 排期发布 → 后续复查。

## 6. 首页榜单与评分规则

### 6.1 每日更新榜

- 用户要求首页能看到每日更新的内容。现阶段按**本站收录时间**展示新收录作品，不把收录日期写成原片首发日期。
- 质量优先，无合格作品时不为每日数量凑片；说明最近更新时间及空状态。
- 榜单展示条数、每天运营发布时间和人工置顶规则待定。

### 6.2 近期热门榜：当前统计近 10 天原作跳转

- 统计范围为北京时间今天及前 9 个自然日，按本站原作观看入口的有效去重点击降序。
- 首页精选、片库卡片、详情中的原作观看入口计入；仅打开详情、点击榜单条目或原平台评价入口不计。
- 当前去重口径：同一浏览器访客、同一作品、同一自然日最多一次；不是跨设备实名人数，不宣称完全防刷。
- 使用共享服务保存汇总，统计失败不阻断原作跳转；数据不可用、过期或无有效记录时显示明确状态。
- 展示名称或说明必须包含“原作跳转”，不称为播放量、完播量或购票量。
- 后续站内放映上线后，再确认有效播放的定义以及新建／切换播放榜的规则；历史跳转数据不转换成播放数据。

### 6.3 口碑高分榜与长期高分

- 已确认方向：提供高评分作品榜，并希望能发现长期保持高分的影片。
- 当前本地试行：站内均分至少 8 分、评分人数至少 5 人，按 `(均分×人数+7×20)/(人数+20)` 排序，页面仍显示真实均分和人数。
- 上述阈值与权重是可调整的实现规则，不是用户确定的永久标准，也不是编辑评分。
- 当前只有实时口碑榜，尚不能证明“连续高分”。后续需保存每日评分快照，再确定持续天数、样本门槛和异常评分处理规则。
- 样本不足时明确说明，不给作品虚构评分、排行或“连续霸榜”标签。

## 7. 访客、账号、评论与评分

### 7.1 默认访客模式

- 不强制注册即可浏览免费内容、查看详情和评价、跳转免费原作。
- 保留访客评论与 1–10 分评分；当前每浏览器对每部作品一份评价，可更新或撤回，可只评分或只写文字。
- 访客评价基于浏览器身份，清除 cookie 或换设备后可能无法恢复修改权；页面应说明边界。
- 评价失败保留草稿并支持重试。其他用户可看到已成功保存的评价，不能用单机存储假装全站共享。

### 7.2 注册与登录

- 页面提供可选择的登录／注册入口；账号需要能跨设备恢复订单和观影权益。
- 建议购买前登录，登录完成后回到原作品或未完成的购买流程，不丢失选片上下文。
- 登录方式（手机、邮箱、第三方等）、找回方式、昵称／头像规则及设备限制待定，本文不默认指定短信服务或微信接入。
- 建议登录后同步收藏；访客收藏与评价是否绑定账号、如何确认归属和去重，需在账号设计时确定，不能按昵称认领旧评价。
- 账号下同一作品只能有一份有效评分；登录前后身份合并的具体规则待定，不能让同一份评价被重复纳入均分。

### 7.3 评价展示与治理

- 分开显示编辑评价、本站观众评价和原平台评价入口。
- 无真实购票记录时不展示“已购用户”标识；外链点击不证明看完，不能标记“已观看”。
- 公开交易前应具备评价举报和运营处理能力；违规内容可隐藏或移除并留处理记录，具体规则待定。
- 不以好评作为观看或退款前提，不通过运营补分制造口碑。

## 8. 单片购买、充值与观影权益

### 8.1 收费方式

- 已确认按片购买方向，拟定 3 元／5 元；不自动固定所有影片价格，也不将市场报告的 70% 分成写成合同条款。
- **建议首个交易版本直接按片支付，不先建设充值钱包。** 用户提到充值不等于已决定采用储值；是否建设余额、最低充值额、有效期和退余额规则均待定。
- VIP／包月、积分、优惠券、打赏、自动续费不是当前首个交易闭环的必要功能；未来引入时另行定义与已购单片权益的关系。
- 支付渠道及支付服务方案待定，实际开户、收费资源或上线收款不由本需求文档自动授权。

### 8.2 下单与付款

| 编号 | 目标行为与验收标准 |
| --- | --- |
| PAY-01 | 下单前展示影片、作者、完整时长、试看内容（如有）、最终应付金额、授权起止及观看范围、退款和下架处理说明；试看长度待定。 |
| PAY-02 | 金额和售卖状态由服务端确认，订单记录价格与权益版本；不能通过修改网页参数以任意低价购买。 |
| PAY-03 | 服务端核实支付成功后才发放权益；取消付款、支付失败或结果未知不得直接显示已购。 |
| PAY-04 | 支付结果暂未同步时显示确认中并可恢复查询；重复回调不重复发权益或重复计入创作者收益。 |
| PAY-05 | 已有有效观影权益时优先显示“立即观看”，避免误导重复购买；到期后是否重新售卖及价格待定。 |
| PAY-06 | 我的订单展示金额、作品、时间、状态及售后入口；换设备登录可恢复查询，不依赖本机访客 cookie 证明购买。 |

### 8.3 已购观看

- 购买后在该作品授权期内反复观看；不能宣传成永久拥有、永久可下载或默认 48 小时租赁。
- 购前展示的期限与购后实际校验一致。授权到期、临时故障、永久下架、退款后的观看处理需要分别定义并向用户披露。
- 已购影片保留订单历史；无法播放时说明原因与处理入口，不静默删除购买记录。
- 播放器应支持暂停、进度、声音、全屏、加载／失败重试及移动端观看；建议支持账号观看进度。清晰度、字幕、并发设备及下载权限待定。
- 未购买或授权失效的用户不能通过公开网页源码取得可直接长期访问的付费正片；播放访问应由服务端核验权益。
- 访客无脚本浏览与免费外链可以保留；不能承诺离线文件模式完成账号、购票或付费放映。

### 8.4 退款与收益关联

- 建立未支付、确认中、已支付、退款中、已退款／退款失败等可追踪状态；订单与资金状态不混为一个前端按钮。
- 退款条件、申请期限、部分退款、下架或授权异常补偿规则待定，必须在真实收费前确定并披露。
- 退款或冲正应关联观影权益及创作者账本，避免观众已退款而创作者收益仍被重复结算。

| --- | --- |
| CRE-01 | 注册用户可申请创作者身份；身份核验、联系方式、收款信息及准入要求待定。通过申请不等于作品自动可售。 |
| CRE-02 | 提交完整成片、片名、简介、时长、类型／题材、封面、试看物料与权利资料；AI 使用情况及必要标识进入审核材料。 |
| CRE-03 | 支持草稿、已提交、审核中、需修改、未通过、待上架、已上架、已下架等状态，反馈原因与后续操作。 |
| CRE-04 | 人工核查完整故事、画面一致性、镜头与剪辑、声音、完成度；粉丝少或不爆款不是淘汰理由，热度不能代替质量。 |
| CRE-05 | 付费上架前确认素材权利、授权范围和期限、价格、分成、结算规则及下架处理；不能仅凭公开链接收费放映。 |
| CRE-06 | 上架与付费条件需经平台审核；创作者修改正片、授权或价格时，不能静默改变已购用户承诺，重要变更应复审。 |
| CRE-07 | 每笔有效付费订单按已约定规则记录收益，区分待结算、可结算、已结算与退款冲正，不把订单总额全部展示为创作者收入。 |
| CRE-08 | 创作者可查看本人作品的订单汇总、收益明细、费用与退款扣减、结算状态；无权查看其他创作者私密数据。 |
| CRE-09 | 分成比例、计提基数、支付／渠道费用承担、税费处理、结算周期、起付额、保底与独家条件均待定，不擅自设定。 |

“每有人支付就获得收益”解释为每笔经核实的有效订单形成可追溯的收益记录，不自动解释为支付瞬间到账或随时无条件提现。

## 10. 内容发现 AI 与片库扩容

- **首批来源：** 小红书、抖音、哔哩哔哩。X 与 YouTube 暂缓，快手不列为首批优先来源。
- **发现原则：** 优先发现爆款、增长快的候选，同时允许优质非爆款；不设最低粉丝门槛。质量决定收录，热度决定搜索优先级。
- **候选记录：** 原作者、准确原片链接、标题、集号、时长、发布时间、发现时间、来源热度及采集时间、可访问状态、证据和审核状态。
- **去重：** 尽量以原作／作者／版本关联多平台链接，避免把同片转发重复算成新增影片；存在疑问时交人工确认。
- **核查：** 区分正片、连载单集、预告、混剪、制作教程和赛事合集；不能因标题含 AI 就判断为 AI 电影。
- **看片：** 不凭简介、点赞量或短暂抽样给出正式全片质量认证；无法访问画面／声音时标为待看片或待核实。
- **发布：** AI 结果先进入候选池，经人工核实、审片后才能正式收录；付费电影额外完成授权与可售审核。
- **运行边界：** 不绕过平台登录、验证码或访问限制；失败时记录原因并允许人工补充。优先来源不代表已接通自动采集。
- **更新能力：** 管理后台应支持补录、修订、审核、上下架、排期和链接失效检查，不长期依赖手工改 HTML 扩容。
- 搜索频率、每日候选量、质量打分表、模型、预算、定时任务和人工复审周期待定；“持续发现”不默认承诺每天固定数量。

## 12. 体验、数据与上线边界

1. 桌面与手机可用，沿用 320／390／820／1440／1920 像素宽度检查，无主要交互遮挡或横向溢出。
2. 键盘可操作搜索、筛选、详情、表单和播放器，弹窗有明确关闭与焦点返回；尊重减少动态偏好。
3. 当前帧选为中文独立产品，不将个人网站的双语或主题功能自动视为帧选已确认需求。
4. 页面、评价、搜索、支付与播放分别有加载、空、失败和重试状态。统计服务失败不阻断免费外链观看。
5. 私密用户数据、密钥、权利文件与付费正片不能进入公开 Git 或公开静态发布产物；仅向相应身份返回所需数据。
6. 发布前明确运营主体、内容分类、发行和放映责任、权利链、支付与结算安排。具体适用路径需结合实际业务核验，本文不代替资质审核或法律结论。
7. 免费外链收录、公开复制视频和本站收费放映分别审核，不把“原平台免费”视为“本站可收费”。
8. 建立评价数据、账号、订单和结算等数据的备份恢复与访问控制；迁移时保留必要身份及签名密钥，不承诺新域名自动继承浏览器 cookie 或收藏。
9. 账号恢复、退出／注销、隐私说明和客服处理需在交易版设计中明确；不能因账号操作丢失应保留的交易凭据，具体保留规则另定。
10. 当前 GitHub Pages 只能提供静态前端，现有本地服务不等于正式线上 API；也不能把个人网站本地上传管理服务直接当作公网交易服务。

### 14.1 核心验收场景

- 访客无账号可完成找片、详情、免费跳转与评价；失败不丢评论草稿。
- 10 天跳转跨日、去重和共享汇总正确，页面不冒称播放量。
- 评分不足不虚构高分榜；无历史快照不显示连续高分结论。
- 未登录购买可登录后返回原作品；付款失败或取消没有观影权益。
- 支付确认延迟可恢复；重复确认不重复授予权益和创作者收益。
- 已购用户换设备登录后可找到订单，在授权期内反复观看；到期后的状态符合购前承诺。
- 退款后订单、权益和收益账本按约定同步处理，可追溯原交易。
- 未审核或无付费授权的作品不能上架收费；创作者只能查看和管理自己的业务数据。
- 拆仓后任一网站可独立启动、测试和发布，不依赖另一个仓库中的文件。

### 14.2 建议观察指标

合格片源数量、审核通过率、原作链接有效率、合格访客到付款转化、真实付款人数、退款率、完播率、30 天第二部购买率、单笔订单贡献和创作者结算及时性。

跳转次数不充当完播，预订意向不充当付款，反复观看同一部不充当购买第二部。具体目标值、完播阈值、去重和观察窗口需在试验前确认；不把市场报告的假设门槛直接视为上线验收标准。
