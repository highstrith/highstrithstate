# 个人作品集网站 · 制作和优化方向

日期：2026-10-30
站点：Highstrith · 橘小桔 — 影像与想象（highstrithstate）
状态：方向文档，不等于已上线改动。代码改动前先按项目 AGENTS.md 读产品需求、软件架构、当前进度，并先备份再改。

## 一、现状判断

- 内容和交互目前还可以，问题在画面太单调。
- 用户喜欢花里胡哨、高设计感的 UI，但不希望花哨影响找作品、发需求这些转化动作。
- 商业化方向在谈：原来是个人作品集，现在想往商业靠，但接客户项目还是卖课程、模板、素材，尚未定；价格区间也未定，本文不编价格。

## 二、核心效果：向前飞的作品区

来源：2026-10-30 在聊天里做的滚动 demo，用户在电脑上试过，感觉还可以。

- 做法：深色底、中央大标题钉住不动，作品卡片散在 3D 空间里；往下滑不是页面上移，而是镜头往卡片群里钻。远的卡片小、斜、带景深模糊，靠近时变大、摆正、变清晰，冲过镜头后从旁边掠走。
- 关键教训（demo 里真实踩过的坑）：
  1. 只靠页面整体滚动钉住，在嵌入面板里会失效，舞台会跟着滑走。
  2. 只靠内部滚动一个信号驱动，滑动到交界会冻在半路，出现标题发灰、卡片飞光的奇怪静帧。
  3. 后来改成多路驱动、逐帧校准、两端手动交还给页面，才在电脑上感觉正常。手机端手感尚未确认。
- 落到真站时的约束：
  - 只用 8 到 10 张最强的封面，不要把全部 20 部作品都塞进飞入区。
  - 中央标题例如“精选放映 / 作品集”，副标题写清类别（AI 短片 · 三维 · 动态视觉）。
  - 只用 transform 和 opacity 做动画，保证流畅。
  - 尊重减动效设置；手机上降级为横向滑动或正常网格，不要硬上 3D 飞入。
  - 飞完要落回干净的作品网格，不能让用户找不到筛选和搜索。
- 真站落点待定：是替换现有作品网格，还是在网格上方单独加一段飞入区，需要用户先定。现有作品网格是 JS 动态生成的，不是静态卡片，不能直接按静态卡片的办法硬贴。

## 三、首屏

- 流动渐变光晕加颗粒质感，不要纯平色。
- 大标题做动效：实心字和描边字交替、逐字或逐行入场，行距收紧。
- 数字人形象加视差和轻微倾斜，鼠标移动时有跟随感，但幅度要小。
- 首屏视频用封面加点击播放，不要自动大声播放；手机上先给海报，点击再播。
- 首屏服务句（商业化用，文案待定）：为品牌与创作者做 AI 短片、三维动画、动态视觉，从脚本、角色到剪辑成片。按钮先留“发项目需求”和“查看服务与报价”两个入口，不要只在页尾留联系方式。

## 四、作品区

- 精选放映做成轮播：中间一张大、两侧露出下一张的边，带进度条和缩略图条，悬停时放大加标签浮现。
- 作品网格保持筛选和搜索可用；筛选标签做成动效小药丸（剧情 / AI 短片 / 三维 / 实验等）。
- 悬停时给视频预览，不要一悬停就全屏或自动出声。
- 作品卡按客户问题分类展示时，每例写清需求、担任角色、可交付成果，不要只写“我做过什么”。

## 五、全站动效系统

- 滚动淡入：元素进入视口时淡入上移，幅度小、时间短。
- 跑马灯：只用在分隔带或页脚一类不抢主内容的位置。
- 按钮：渐变填充、磁吸跟随，悬停有反馈但不闪烁。
- 滚动时文字明暗变化：大标题随滚动由亮变灰、段落逐行变亮变暗，借鉴 Artocea 的做法，幅度要克制。
- 全站滚动保持缓动，不要生硬跳格；不要自定义鼠标到影响点击的程度。

## 六、配色与排版参考（只借感觉，不照搬）

- 本站主方向：深底加孔雀蓝 / 蓝绿点睛，配暖金细节，呼应用户自己的配色习惯；联系和报价区保持干净。
- Artocea（已实测）：近黑底、白字、暖米色卡片、橙色点睛；大标题居中、全大写、行距紧；案例轮播露边、评价卡叠着滚动切换。
- Hello World（只实测到开场故事）：深藏青加载页、浅蓝白超大窄体百分比数字、3D 房间加像素风、滚动推进故事、按住更新交互。它的主页面作品区因被开场盖住、检查浏览器卡住，未实测到配色和排版，不能当成已确认的参考。
- 两家共同点：先用身份加数字建立可信度，再用大字口号和网格结构撑场面。本站可以借节奏，不要把它们的文案和结构直接抄过来。

## 七、商业化落地（待定项，不编）

- 服务分类先按三类写：AI 短片、三维动画、动态视觉与后期。
- 流程写五步：需求沟通、脚本与分镜、角色与资产、动画与剪辑、成片交付；并写清修改次数、交付格式、版权归属。
- 报价先写“按项目报价”，具体区间等用户定。
- 不要在未确认前把课程、模板、素材销售写成已上线业务。

## 八、落地顺序

1. 首屏加配色系统：先把深底、点睛色、大字动效、数字人视差做稳。
2. 作品区动效：精选轮播、悬停预览、筛选动效，再单独上向前飞的飞入区。
3. 全站小动效：跑马灯、按钮、滚动淡入。
4. 商业区：服务、报价、流程、联系入口。

## 九、性能与可用性底线

- 动效只用 transform 和 opacity，图片用已有的优化图，不要直接上原图。
- 减动效用户看到静态版；键盘和屏幕阅读器仍能走到作品、筛选、联系。
- 每次改动先备份 index.html 及相关 CSS / JS，改完在本地用 serve.js 预览，确认无控制台报错、无横向溢出、手机版不挤版，再考虑发布。
- GitHub Pages 是公开静态站，本地管理页的能力不要误当成线上能力。
