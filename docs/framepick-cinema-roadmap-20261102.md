# 帧选榜单维护与短片放映路线

最新确认（2026-11-04）：目前没有真实用户和可供消费的短片，当前不开发支付系统，短片支付留到后续。近期优先验证用户需求、积累内容并完善免费发现与观看体验；已有模拟购票保留为原型。下方涉及购买、支付与收益的流程均为后续规划，不是当前实施范围。

早期影院方向：帧选以AI电影线上影院与创作者发行作为长期目标，未来收费曾拟优先单片购买。用户已选择**购买后在作品授权期内反复观看**。拟定3元／5元档位，具体分成比例、结算周期和创作者定价权限待定；原“VIP解锁更多外链”不再作为主收费流程。

观众流程：发现电影→了解简介／试看→账户购买→进入我的片库→授权期内反复观看→评价。创作者流程：账户入驻→作品草稿与授权资料→提交审片→补充或通过→确认价格与授权期上架→查看每笔订单、待结算收益及结算明细。运营需要控制质量、授权、上下架及退款。访客可以发现和评价，真实购买需可恢复的账户与服务端权益记录。

质量目标按完整成片审查故事、镜头／连续性、表演／角色表达、声音与剪辑完成度；热度和粉丝量不替代审片。现有系列单集仍归免费发现，不自动作为付费电影出售。每笔支付在服务端确认后记录创作者待结算收益，退款作冲正；记账与实际结算分别展示，不承诺付款后立即可提现。

页面调整前查看[PeerTube开源视频发布平台](https://github.com/Chocobozzz/PeerTube)及其[许可证](https://github.com/Chocobozzz/PeerTube/blob/develop/LICENSE)，并参考[Vimeo OTT单片购买／租赁产品结构](https://help.vimeo.com/hc/en-us/articles/12427153706897-Creating-a-purchase-rental-product-on-Vimeo-OTT)。前者整套平台超过本次页面范围，后者仅作为产品模式参考；本轮未复制代码或选择托管／支付供应商。

2026-11-02。用户已确认：主页包含每日更新、近10天热门、高分榜。最初选择本站有效播放量，后因当前外链片库阶段，最新改为**近10天本站原作跳转次数**；未来站内放映再单独切换或增加播放榜。希望提供40分钟内、具有完整叙事与高完成度的AI影片，支持单片3元或5元消费、创作者发布及按订单分成。观看权益已确定为作品授权期内反复观看；最终票价、每部作品授权截止日期、分成比例及结算周期待确定。

## 当前能用到哪里

本地首页已展示三个榜单。每日更新从现有公开片库按收录日期排序；站内口碑从共享评价API更新；近10天热门接入本站共享原作跳转统计，同一浏览器访客每部作品每天最多一次。当前没有测试填充数据，真实跳转发生后自动入榜。页面明确标注跳转次数，未把外链点击算作观看，未补造原平台播放量。

当前三部作品依然是免费外链的系列单集，不自动认定为已通过“完整电影／40分钟内授权放映”审核。网站没有售票、创作者自助发布、支付分账或自动搜片上线能力。本轮不发布网站、不创建收费资源。

## 扩充的是作品库，榜单自动取数据

建议让三个渠道汇入同一个候选池：

| 渠道 | 带来什么 | 谁决定上架 |
| --- | --- | --- |
| 专门搜片AI | 小红书、抖音、哔哩哔哩的候选、作者与原链接、热度证据、查证时间 | 运营完整看片后审核 |
| 运营主动策展 | 原创短片、优质连载、新创作者和主题片单 | 运营审核 |
| 创作者投稿 | 作品文件／预览、简介、物料、时长、授权信息 | 运营审核，付费放映另确认商业授权 |

流程统一为：**待核实 → 待看片 → 待补资料／不收录／通过 → 排期 → 上架 → 维护或下架**。AI负责发现、去重和整理证据，不能只看热度、封面或文字就给出正式质量评分。粉丝数不设门槛。原链接相同的投稿合并；同电影不同集、预告、花絮分别标注，不能作为多部完整影片重复上架。

每部作品至少维护：稳定ID、标题、作者、简介、类型／题材、完整片或系列单集、总时长、原作链接、封面及来源、首次收录时间、原片发布时间、审核状态与理由。后续放映再增加授权凭证、授权范围／期限、试看、正片资源、价格分、观看期限、创作者账户和上下架记录。**介绍更新不重置首次上架日期，避免旧片反复霸占新片榜。**

## 三个榜单的更新规则

| 榜单 | 当前实现 | 后续数据生产 |
| --- | --- | --- |
| 每日更新 | 最近收录优先，同日保持策展顺序，展示最多5部；显示今日收录数或真实最近收录日 | 后台审核上架后写首次上架日期，不要求每天凑数量 |
| 近期热门 | 北京时间今天及前9个自然日，本站原作跳转去重次数降序；展示最多5部，来源／窗口错误或统计失败时如实提示 | 共享API按访客／作品／日去重并持久化；仅原片观看外链的原生点击计入 |
| 口碑高分 | 试行均分≥8、至少5人评分；按人数加权排序，显示真实均分与人数 | 共享评价聚合，付费放映上线前增加已购／已观看标记与异常评分处理 |

口碑排序试行公式：`(平均分 × 人数 + 7 × 20) / (人数 + 20)`。7分与20份先验只用于排序，不作为用户看到的评分，不生成虚构评价。这个规则缓解极小样本满分抢榜，但当前cookie访客评分不是防刷票身份体系。“长期高分”以后再通过每日快照验证连续上榜天数；当前不显示虚构“连续7天第一”等标签。

未来有效播放建议规则（待放映模块实施，不是当前跳转榜口径）：实际播放累计达到`min(120秒, 片长20%)`；拖动跳过、后台挂起和播放器不可见的时间不计；同一已识别观看者同一作品同一北京时间自然日最多计1次。购买订单与有效播放分开统计，买了没看不计播放、重复回放不重复刷当日热度。付费片仅在真实支付授权后播放。最终阈值作为运营配置，变更应记录生效时间。

## 现在怎样补片

当前没有片库管理后台，仍以`reel/index.html #filmGrid`的作品卡为目录源。每新增一部：

1. 先完成上述核实和审片，确认原链接、作者、封面来源及真实时长；无正式编辑评分就保留空`data-score`。
2. 添加唯一`data-film`的完整卡片，填正确的`data-date`、分类、来源、简介和链接；同步类型与收录数量文案。不把未授权外链改成付费入口。
3. 重启本地`node serve.js`，让评价服务读取新增作品ID；回归筛选、详情、评价、每日更新以及无脚本原片入口。审核本地版本后再单独执行正式发布流程。

每日更新会自动读取新增卡片，口碑榜在评价达到门槛后自动入榜，无需人工填写排名。建议先每周精选少量真正看完的作品，日常查新和维护链接；“每日更新”描述榜单按日呈现，不承诺每天硬上新。

近期热门改由共享访客API自动产生：GET `/api/framepick/outbound/summary`返回`{metric:'outbound-clicks',windowStart,windowEnd,updatedAt,films:[{filmId,outboundClicks}]}`。前往原作观看的原生点击通过POST记录，后端决定日期与去重；前端校验10天窗口和计数，成功后重新取榜单。旧`reel/ranking-data.js`已移除，不再维护手填快照；统计失败不阻断原作打开，正式Pages还需部署共享API。详情见[跳转统计说明](framepick-outbound-20261102/README.md)。

## 下一步建设顺序

1. **先做片库后台**：从作品卡迁移到统一作品表，加入候选池、去重、审核、排期、下架和变更记录；发布公开字段到静态站，私密资料保留服务端。这样补片不再需要改HTML。
2. **再做创作者工作台**：账户、作品草稿、投稿／修改、审核反馈、物料与授权提交；上传不直接公开，创作者只能管理自己的作品。先邀请少量创作者试运营，验证完整审片流程。
3. **接通授权放映与统计**：试看、正片播放、观看进度、服务端有效播放汇总，再决定增加或切换本站播放榜。外链发现与本站放映清楚分开，原跳转历史不改称播放。
4. **最后开放单片购买与创作者收益**：服务端定价（整数分）、真实支付回调、订单与观看权限、退款和到期；收益按成功订单生成可核对账本，退款作冲正，不因前端“支付成功”或刷新页面重复记账。创作者看到订单来源、待结算／可结算／已结算及扣减明细，正式比例与结算周期经双方确认后执行。

3元／5元是用户提出的票价方向，不是已上线价格；分成比例不擅自设定。首版以单片购买为主，原VIP精选索引方案暂停作为主收费流程；如以后增加会员，另行定义与单片权益的关系。当前免费原平台视频不会直接作为收费正片转售。
